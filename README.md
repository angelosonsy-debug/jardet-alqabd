# جردة القبض — Payroll Reconciliation System

نظام متخصص لإدارة ومتابعة توزيع المرتبات وجرد النقدية لعدد محدود من السرايا/الجهات،
وليس نظام إدارة موارد بشرية شامل.

## نقطة لم تُحسم من المرفقات — تحتاج تأكيدك

ملف HTML الأصلي يفترض ضمناً أن الكشف كله في جدول واحد. لم تتوفر عينة Word حقيقية
متعددة الصفحات، فبُني `wordParser.ts` باستراتيجيتين (موثقتين بالتفصيل في أعلى الملف):

1. **جدول منفصل لكل صفحة** — الافتراضي عند وجود أكثر من جدول.
2. **فواصل صفحات صريحة داخل جدول واحد** (`w:br w:type="page"`) — كخيار احتياطي.

إذا لم تطابق ملفاتك الفعلية أياً من الحالتين، ترفع نموذج Word حقيقي (بأسماء وهمية)
لضبط الاستراتيجية بدقة. شاشة المعاينة تتيح تصحيح أي اسم/مبلغ يدوياً قبل الاعتماد
في كل الأحوال، فلا يضيع عملك حتى لو احتاج الاستخراج تعديلاً لاحقاً.

## ربط Supabase

1. أنشئ مشروعاً جديداً على [supabase.com](https://supabase.com).
2. من `Project Settings → API` انسخ `Project URL` و`anon public key` إلى `.env`.
3. طبّق المايجريشن بالترتيب (كلها داخل `supabase/migrations/`):
   ```bash
   npx supabase login
   npx supabase link --project-ref <project-ref>
   npx supabase db push
   ```
   أو الصق كل ملف بالترتيب (0001 ثم 0002 ثم 0003 ثم 0004) في `SQL Editor` بلوحة تحكم Supabase.
4. **إضافة المستخدمين المصرح لهم** (لا يوجد تسجيل عام مفتوح):
   من `Authentication → Users → Add user`، أضف بريد وكلمة مرور لكل شخص مصرح له.
   كل حساب يحصل تلقائياً على نفس صلاحيات العمل (لا يوجد Admin/Editor/Viewer).
5. فعّل Realtime على الجداول (يتم تلقائياً عبر migration 0001، تأكد من ذلك في
   `Database → Replication` إذا لم تظهر التحديثات الفورية).
6. **Service Role Key ممنوع في الواجهة الأمامية نهائياً** — غير مستخدم في أي مكان
   بالكود، والحماية الفعلية تتم بالكامل عبر سياسات RLS، وكل عملية مالية (قبض، تعديل
   مبلغ/اسم، جرد نقدية، إغلاق/فتح دورة) تمر حصراً عبر دوال RPC معاملاتية (`security
   definer`) تضمن تسجيل الحدث في `audit_logs` في نفس الـ transaction — لا يمكن لأي
   مستخدم تعديل البيانات المالية مباشرة متجاوزاً السجل.

## PWA

تم إعداد `vite-plugin-pwa` بالكامل (manifest باللغة العربية واتجاه RTL + service
worker + أيقونات placeholder في `public/icons/`). بعد النشر، "إضافة إلى الشاشة
الرئيسية" من المتصفح على Android/iPhone يثبّت التطبيق كتطبيق مستقل. **استبدل
أيقونات placeholder بأيقونة المشروع الفعلية قبل النشر النهائي.**

## اختبارات القبول (البند 17 في الطلب)

جميع أرقام الحسابات مُختبرة آلياً في `src/lib/__tests__/aggregation.test.ts` وتطابق
المطلوب تماماً: 62 فرد/20,315.20 جنيه، مقبوض 6,822.40/متبقي 13,492.80، والتسوية
(زيادة/عجز/تطابق). الاختبارات اليدوية المتبقية (الاستيراد الفعلي من Word، التزامن
بين جهازين، تسجيل الدخول) تحتاج مشروع Supabase حقيقي مربوط — غير ممكن محاكاتها بدون
بيانات اعتماد فعلية، ومذكورة هنا كخطوة تالية بعد الربط.

## قيود معروفة (موثقة بالتفصيل داخل الكود)

- اكتشاف ترقيم الصفحات من XML لملف Word هو استدلال وليس مضموناً 100% لحالة التفاف
  تلقائي بلا أي فاصل صريح ولا جداول منفصلة — راجع التعليق أعلى `wordParser.ts`،
  وراجع "نقطة لم تُحسم" أعلاه.
- أيقونات PWA في `public/icons/` هي placeholder (حرف "ج" بسيط) — استبدلها بشعار
  المشروع الفعلي قبل النشر.
- استخراج PDF لكشوف الرواتب غير مطلوب حسب الطلب (الملف الأصلي فقط .docx)، ولم يُبنَ.
